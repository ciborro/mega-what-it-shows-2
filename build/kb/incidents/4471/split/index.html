What each problem is

parser — the shared parser reads every date month first. Day-first tenants get day and month swapped: 7 April becomes 4 July.

hint — booking-v3 prints MM/DD/YYYY under its date field. People type month first, as told, and the form reads the value the tenant’s way. Same symptom as parser, different code, different fix. The table above marks it “no ticket of its own”; #2 is that ticket.

The reports in the footnote, which the desk read as a one-day move, stay counted under parser, where their tenant files them. Their bodies describe a date shifted by one day rather than a swap, so check them again once the parser fix ships.

How a report is placed

  1. Count each report once: the export pages overlap, so the same id can appear twice.
  2. Ask the tenant, not the reporter’s browser (causes.ts): a day-first tenant on a booking-v3 form is hint; every other day-first report is parser.

Intake’s tag is not used. It is a guess from the reporter’s browser and often names the wrong cause: compare the “tagged as” column above.

For the desk

  • Merge into a ticket only reports with the same cause, not the same subject.
  • When a new date report comes in, place it with the steps above and add it to that cause’s ticket.
